What problem are we solving?

Multiple producers generate items into a shared buffer while consumers remove and process those items. We must ensure correctness (no data races), avoid deadlocks, and keep performance high under contention.

Synchronization Techniques Explained

Each technique solves the same producer–consumer problem but emphasizes a different tradeoff. This section explains how each one works conceptually and when it should be used.

Mutex-only (Busy-wait)

This approach uses a single mutex to protect shared state. Threads repeatedly attempt to acquire the lock and check buffer conditions. While simple to reason about, this causes threads to actively wait, consuming CPU cycles even when no progress is possible.

Best suited for very small critical sections with extremely short wait times.

Semaphores

Semaphores use counters to represent available buffer slots and items. Threads block efficiently when counters reach zero, allowing the OS to sleep threads instead of wasting CPU time.

Ideal for bounded buffers and fixed-size resource pools.

Condition Variables

Condition variables allow threads to wait until a condition becomes true. Threads sleep instead of spinning and wake only when signaled that progress may be possible.

Clean logic and scalable signaling but conditions must be re-checked due to spurious wakeups.

Unbounded Queue (Linked List)

This approach removes the full buffer condition by dynamically allocating nodes for each item. Producers never block due to capacity.

The tradeoff is unbounded memory growth if production outpaces consumption.
